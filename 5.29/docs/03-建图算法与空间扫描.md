# 建图算法及其对后续空间扫描的加速作用

本文说明矿井巷道几何处理流水线中**逻辑拓扑图**的构建机理，并着重论述：建图并非仅将几何结果封装为图结构，而是将昂贵的全图空间两两扫描，压缩为一次有界候选检索与持久化邻接关系；下游步骤因此得以沿边遍历与局部查询推进，而不必对原始线段集合反复作全局空间扫描。总体架构见 `docs/01-architecture-zh.txt`，分步工作机制见 `docs/02-methods.md`。

行文遵循 `重要原则.txt`：书面语、正式语气；产物名称与既有文档保持一致；以算法机制为叙述单位，必要时仅引用稳定的产物与边类型称谓。

---

## 一、问题背景

巷道图纸导出后，线段数量可达数千至数万。若每一步几何判定均对全体线段做两两比较——例如端点是否接近、两墙是否平行且投影重叠、碎线是否触及某条走廊边界墙——则单次扫描的比较次数为线段规模的平方量级，且同一对线段可能在直墙合并、平行配对、残差附着、中心线修补等环节被重复检验。

因此，流水线将处理划分为「**建图阶段的空间扫描**」与「**建图完成后的拓扑运算**」两类工作：

| 阶段 | 空间操作的对象 | 主要目标 |
|------|----------------|----------|
| 建图 | 原始或归一化后的线段集合 | 在可控复杂度内发现邻接与平行关系，并写入逻辑拓扑图 |
| 建图之后 | 已写入的节点与边 | 沿边枚举、按连通分量索引、在局部邻域内做几何复核 |

**建图对后续空间扫描的加速作用**，正是指：后续步骤将「在全图线段上搜索可能相关的对象」替换为「读取已确认的邻接或平行边，仅对边所连接的有限对象做几何运算」。平行墙组等索引结构进一步把全图边集合缩小到连通分量内部。

## 二、建图总览与数据约定

### 2.1 两类表示

流水线在几何表示与逻辑拓扑图之间交替推进：

1. **几何表示**：端点坐标、墙段列表、碎线列表等，供坐标运算与可视检查。
2. **逻辑拓扑图**：节点表示墙段、碎线或巷道候选中心线；边表示端点邻接、平行配对或碎线附着关系。

每个完整处理步骤**只接受一张**逻辑拓扑图作为主要输入，**只产出一张**作为主要输出。中间审计列表不得替代拓扑图成为下游正式输入。

### 2.2 主干拓扑产物（名称稳定）

| 顺序 | 产物 | 节点含义 | 边所固化的空间关系 |
|------|------|----------|-------------------|
| 1 | 归一化端点图 | 归一化后的直线段 | 端点邻接（间隙、夹角、近平行或近正交） |
| 2 | 平行逻辑图 | 直墙与残差碎线 | 端点邻接；直墙之间的平行配对 |
| 3 | 中心线逻辑图 | 巷道候选中心线 | 中心线端点邻接与平行关系 |
| 4 | 残差图 | 碎线（及与之相关的边界墙） | 碎线接触、走廊—碎线接触、碎线平行、走廊—碎线平行 |
| 5 | 结构图 | 修补后的巷道中心线结构 | 供后续标注挂接、设施挂接等空间归属使用的底图 |

平行墙组（平行边的连通分量）**不是**巷道候选，也**不是**网络节点，仅作为搜索加速索引。

### 2.3 尺度约定

端点链接间隙、平行带宽、附着容差等长度类阈值，均相对于图面中位巷道宽度或平行边上的配对宽度缩放，避免在图纸坐标中写死绝对距离。尺度随候选列表或中心线逻辑图向下游传递。

## 三、建图算法

建图按「先局部连续性、再横向平行、再走廊中心线、再残差附着」的顺序推进。各子功能分步单独运行，禁止用单一总脚本串联全部子功能。

### 3.1 端点邻接图的构建

**目标**：将导出几何中的直线与圆弧转为节点，在端点彼此接近且满足角度条件的图元之间建立端点邻接边。

**空间扫描方式（建图时）**：

- 以端点链接间隙为网格单元边长，将各线段端点落入平面网格单元。
- 仅对同一单元及相邻单元内的端点对计算欧氏距离；超出间隙者不予建边。
- 对进入距离门限的候选对，再计算方向夹角，标记近平行、近正交等属性。

**加速含义**：端点邻接的发现成本由全体端点两两比较，降为「按网格局部邻域比较」。圆弧圆角分类与方折检测均在该邻接关系上展开，而不再对无关远距离图元做无谓配对。

归一化（可信圆角裁端、删除圆弧）之后，在仅含直线的集合上重建端点邻接图，作为直墙合并的正式拓扑输入。

### 3.2 直墙合并与残差碎线分离

**目标**：在归一化端点图上沿端点邻接边搜索共线链，将可合并短段并成长直墙；其余短段归入残差碎线。

**判定要点**（均在已有邻接边上局部检验，而非全图重扫）：

| 条件 | 含义 |
|------|------|
| 端点接近 | 链上相邻段间隙小于连续性阈值 |
| 近共线 | 相邻段方向夹角小于角度阈值 |
| 横向偏移 | 链上段中心线横向偏离小于横向容差 |
| 正交分支 | 开口处存在近似正交分支时，不强行共线合并 |

直墙进入后续平行配对；残差碎线保留原图元句柄，进入平行逻辑图的碎线节点，语义留待更后阶段标注。

### 3.3 平行逻辑图的构建

**目标**：以直墙与碎线为节点，固化两类关系——端点邻接与直墙平行配对。

**平行配对的空间扫描方式（建图时）**：

1. **方向分箱**：按线段方向角将候选墙段划入若干角度箱，仅在同箱或相邻箱内配对，排除明显不平行的远角组合。
2. **横向—轴向扫描**：在同一方向组内，将中点投影到法向与轴向；按横向坐标排序后，用滑动窗口仅保留墙间距落在「中位巷道宽度导出的带宽」内、且轴向投影区间有重叠的候选对。
3. **几何复核**：对候选对检验夹角、墙间距与投影重叠比，通过者写入平行边。

对长直墙，优先采用上述「方向分箱 + 横向轴向扫描」，避免仅依赖轴对齐包围盒网格时，长线段占满大量单元而导致候选对爆炸。轴对齐包围盒邻域检索仍用于部分接触类判定（见残差图）。

**平行墙组**：平行边的连通分量编号写入摘要，供下游在分量内部枚举边，而不必每次遍历全图平行边集合。

**输出**：平行逻辑图——第 1 部分的最终拓扑产物，亦是巷道候选生成与残差图构建的共同事实层。

### 3.4 由平行边生成巷道候选与中心线逻辑图

**目标**：每条直墙—直墙平行边对应一个墙对与一个巷道候选；由投影重叠区间计算中心线；再以候选中心线为节点，建立与平行逻辑图同构的端点邻接边与平行边。

**加速含义**：

- 候选生成**不**再对全体直墙做两两平行搜索，而是**直接枚举平行逻辑图上已确认的平行边**。
- 平行墙组可作为可选索引，将枚举范围限制在同一连通分量内。
- 中心线逻辑图再次把「候选之间是否可轴向延续、是否横向平行」固化为边，供修补与语义映射沿边查询。

本步不判定主巷、横档或腔室；不在平行配对完成后再按墙间距二次过滤候选。

### 3.5 残差图的构建

**目标**：在平行逻辑图的墙与碎线事实层上，为碎线建立专门的残差拓扑，描述四类关系：

| 边类型 | 含义 |
|--------|------|
| 碎线—碎线接触 | 端点在缩放间隙内首尾相接 |
| 走廊—碎线接触 | 碎线触及某条走廊的边界墙 |
| 碎线—碎线平行 | 间距落在巷道宽度带内的平行碎线对 |
| 走廊—碎线平行 | 碎线与已确定的走廊边界墙平行 |

**空间扫描方式（建图时）**：

- **接触类**：以附着容差扩展轴对齐包围盒，经平面网格哈希仅生成包围盒接近的跨集合候选对（碎线对墙、碎线对碎线），再计算真实段间距离或端点间隙。网格只作索引，不分割几何对象本身。
- **平行类**：复用与平行逻辑图相同的方向分箱与横向轴向扫描，将候选限制在巷道宽度带与投影重叠条件附近。

**残差簇**：

- 第一版划分：仅沿碎线接触边求连通分量。
- 第二版划分：在碎线接触边与碎线平行边的并集上求连通分量，作为附着区域语义阶段的主划分。

建图完成后，巷壁候选挑选、中心线延伸与合成连接器、逐碎线语义标注等，均在残差图的边与连通分量上推进，而不对全图碎线与全图墙段重新做无索引的两两扫描。

### 3.6 结构图

在中心线修补与残差语义稳定之后，流水线汇总得到**结构图**（巷道中心线逻辑结构）。结构图将走廊几何与拓扑关系固化为后续空间归属的底图：标注簇挂接、设施实例挂接等步骤，以结构图中的中心线段为检索对象，按点到线段距离判定归属，而不再回到原始墙线图层做全图几何重建。

## 四、建图对后续空间扫描的加速机理

### 4.1 从「全图两两扫描」到「一次建边、多次复用」

设线段规模为 $n$。朴素空间扫描在每一步对潜在相关对做 $\Theta(n^2)$ 次几何检验。建图算法将检验分为两层：

1. **候选生成**（网格邻域、方向分箱、横向滑动窗口）：输出规模远小于 $n^2$ 的候选对集合；
2. **精确复核**：仅对候选对计算间隙、夹角、墙间距、重叠比等。

通过检验的关系写入边之后，下游步骤的主导复杂度转为「边数」或「连通分量规模」量级。只要边的平均度数有界，后续多次语义与修补运算即可避免再次支付全图平方级扫描代价。

### 4.2 关系固化：把几何谓词变成可遍历的边

| 几何谓词（建图前需扫描） | 固化后的图操作（建图后） |
|--------------------------|--------------------------|
| 两端点是否在链接间隙内 | 查询端点邻接边 |
| 两直墙是否平行且重叠 | 查询或枚举平行边 |
| 碎线是否触及某走廊墙 | 查询走廊—碎线接触边 |
| 碎线是否与边界墙共线平行 | 查询走廊—碎线平行边 |
| 哪些墙同属一组平行关系 | 读取平行墙组（连通分量索引） |

因此，中心线修补中的「提升巷壁」「沿对侧墙延伸中心线」，以及残差语义中的「凹进、辅巷道」判定，均可先沿边收集有限邻居，再在局部做形状规则检验。

### 4.3 索引层次

建图形成的加速结构可归纳为三层：

```text
几何线段集合
    │  平面网格 / 方向分箱 / 横向轴向扫描   ← 建图时的空间扫描
    ▼
逻辑拓扑边（邻接、平行、接触）
    │  边枚举与邻接表查询                 ← 建图后的主路径
    ▼
连通分量索引（平行墙组、残差簇）
    │  分量内局部搜索                     ← 进一步缩小扫描域
    ▼
结构图底图上的点—中心线挂接
       点到有限中心线段的距离查询         ← 下游标注与设施空间归属
```

平行墙组与残差簇**不替代**平行边或接触边本身，只提供「先定位到相关子集，再在子集内运算」的索引。

### 4.4 对下游空间归属步骤的意义

结构图一经建成，后续以中心线为参照的空间扫描具备如下性质：

1. **检索对象降维**：从「全部原始墙线与碎线」降为「走廊中心线段集合」，规模通常显著小于原始图元数。
2. **拓扑可过滤**：可按节点角色（主走廊、辅巷等，若已标注）限制挂接候选，避免无关几何参与最近邻竞争。
3. **阈值可随尺度传递**：挂接距离阈值可借用建图阶段写入的中位巷道宽度及点到中心线距离的统计量自适应推断，使空间扫描的搜索半径与图面尺度一致，减少过宽半径导致的无效比较。

上述性质表明：建图阶段支付的空间扫描与关系固化成本，是整条流水线后续多次空间查询的公共前置投资；省略建图而反复对原始几何做全局扫描，既增加计算量，也难以保证各步骤使用同一套邻接与平行事实。

### 4.5 边界说明

- 建图时的网格与分箱**只生成候选**，不改变线段几何；最终关系以精确几何复核为准。
- 中心线逻辑图在局部图规模（数十至数百条候选）下可采用全体候选两两检验；整图数千条候选时，原则上应复用与平行逻辑图相同的空间索引策略。
- 合成连接器仅修复中心线几何连续性，不是横档或腔室分类；残差语义阶段的标签与修补挑选阶段的可能巷壁标签不得混用。

## 五、小结

建图算法以端点邻接、平行配对与残差附着为主线，将图纸线段组织为可递进的逻辑拓扑图序列，并最终形成结构图底图。其空间策略是：**在建图时用网格邻域、方向分箱与横向轴向扫描把平方级比较压成有界候选集；在建图后用边与连通分量索引替代全图空间重扫**。由此，巷道候选生成、中心线修补、残差语义以及后续标注与设施的空间挂接，均得以在已确认的拓扑邻域内完成，从而实现相对朴素全图两两扫描的实质性加速，并保证各步骤共享同一套几何关系事实。
