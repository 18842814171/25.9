# 阶段四：横档与腔室识别

本文档规定阶段四的职责边界、拓扑基础与分步实现方案。阶段四在 Step 3B 残差图与中心线修复结果之上，为残差区域赋予语义角色，并据此约束后续主巷网络构建。语气与结构遵循项目 `重要原则.txt`：每个完整步骤单独运行脚本、每步仅输入与输出各一张逻辑拓扑图、产物名称保持稳定。

语义分类按全局碎线流水线执行：先识别凹进（三边接触链且外侧两腿平行），再标记与已知巷壁平行的疑似主墙，再识别辅巷道平行对，其余归为未分类。几何尺度相对中位巷道宽度或平行边配对宽度缩放。

## ⚠️ 已知案例：Niche 三连链贪心冲突

> **图例**：`2026.1-1part-巷道`，RC003 区域（见 `lb-2026.1-1part-巷道_attached_regions.png` 右下段）。  
> **现象**：一侧 954/953/955 三根线完整标为 NICHE；另一侧 958/88D 标为 NICHE，956 却是 UNCLASSIFIED，且 958 与 88D 在图上相距较远，看起来像“两根分开的紫线”，不像标准的三线凹进。

### 实际分类结果

| handle | 语义 | niche_chain | 说明 |
|--------|------|-------------|------|
| 954, 953, 955 | NICHE | `[954, 953, 955]` | 标准 U 形：两竖腿平行，中间横档 953 touch 连接 |
| 958, 88D, 934 | NICHE | `[88D, 934, 958]` | 算法最终采用的 niche |
| 956, 951 | UNCLASSIFIED | — | 本应组成另一组 niche，但未生效 |

### 图结构里其实有两套合法 niche

**候选 A（算法先占用）**：`88D — 934 — 958`

- 平行腿：`88D ∥ 958`（`stub-stub-parallel`，width≈6.17）
- 中间线：934（touch 连接 88D 与 958）
- 934 在 y≈583，958/88D 在 y≈585–598，**空间上分散**，第三根 934 不显眼

**候选 B（更符合局部 U 形直觉）**：`956 — 951 — 958`

- 平行腿：`956 ∥ 958`（width≈5.4，与对面 954∥955 同宽）
- 中间线：951（水平横档，端点分别 touch 956 与 958 顶端）
- 几何上与对面 `954—953—955` **对称**，是用户期望的 niche

两套三连链在残差图中**同时成立**（`_find_niche_triples` 均能发现），但 **958 只能属于一个 niche**。

### 根因：按边遍历顺序贪心消费

`stub_classify.py` 的 niche 规则：

1. 找平行腿对 `leg_a ∥ leg_c`
2. 找中间线 `mid`，满足 `leg_a —touch— mid —touch— leg_c`
3. 命中后三条线标 NICHE，并从候选池 `remaining` 中 **discard**

处理顺序为**先到先得**：

```
#1  ['88D', '934', '958']  → 消费 958、88D、934
#8  ['956', '951', '958']  → 958 已不在 remaining，整条链跳过
```

因此 956、951 落入后续规则均未命中 → UNCLASSIFIED。这不是“956 与 958 不构成 niche”，而是 **958 被另一组更先发现的 niche 抢走**。

### 与对面 954/953/955 的对比

| | 对面 954/953/955 | 本侧（实际） | 本侧（期望） |
|--|-----------------|-------------|-------------|
| 三连链 | 954—953—955 | 88D—934—958 | 956—951—958 |
| 三根线空间关系 | 紧凑 U 形 | L 形、第三根 934 偏远 | 紧凑 U 形 |
| handle 冲突 | 无 | 958 被两组共享 | — |

因为此情况仅属于个例，未造成大幅误差，故必须在生成的数据中进行**人工校正**，表明“不采用”此数据。同时人工重写新数据，记入“《文件名》-corrected_labels”。

### 后续改进方向（不实现）

- 多个合法三连链共享同一腿时，**择优**而非先到先得（如优先几何紧凑的 U 形、优先等长腿对）
- 或限制：长腿（如 88D 长 14.9m）与短 stub 组成的 niche 不应抢占短 stub 的局部 U 形组合

相关实现：`stage4/stub_classify.py` → `_find_niche_triples`、`classify_all_stubs`。

## 一、阶段定位

### 1.1 职责

阶段四回答三类残差语义问题：

1. **横档（H 形连通器，`=` 形，`detail_type: connector`）**：短残差段是否横向连接两条平行主巷候选，而非沿主巷轴向补墙。
2. **腔室（`口` 形，`detail_type: chamber`）**：单走廊附着且残差围合封闭空间，应从主巷宽度统计与中心线连通中排除。
3. **Niche（`几` 形，`detail_type: niche`）**：单走廊附着但未围合的侧向凹进，非主巷轴、非横档。

阶段四**只做识别与标注**，不在此阶段合并主巷网络，也不改写 Step 2A、Step 2B、Step 3A 的几何产物。

### 1.2 与 Step 3B 已完成功能的分工

Step 3B 当前三条脚本解决的是**中心线几何连续性**：

| 脚本 | 输出拓扑图 | 作用 |
|------|-----------|------|
| `build_residual_graph.py` | `residual_graph.pkl` | 残差段与边界墙的四种边关系 |
| `pick_corridor_wall_candidates.py` | `residual_graph_tagged.pkl` | 挑选可能巷壁残差段 |
| `fix_centerlines.py` | `centerline_graph_fixed.pkl` | 提升巷壁、延伸或合成连接器中心线 |

其中 `centerline_synthesis.py` 实现的**合成连接器**（图中紫色虚线）指：平行残差分量在轴向两端均已挂接既有走廊拓扑时，沿平行方向补一段中心线。该机制**不是**横档识别，也**不是**腔室判别。阶段四将明确区分这三类语义，避免名称混用。

### 1.3 不在本阶段范围内

- 测点、标注、图例的语义融合（属更后阶段）。
- 单一总脚本串联 Step 3B 与阶段四全部流程。
- 在识别完成之前修改 `docs/0701.md` 等已稳定文档（程序定型后再统一修订）。

## 二、基础：已有拓扑与待补模块

### 2.1 输入拓扑图（阶段四唯一定期输入）

阶段四的标准输入为 **已映射走廊编号的残差图**：

```
step3B/output/{stem}_residual_graph.pkl
        │
        │  （运行前需用 centerline_graph.pkl 写入 corridor-stub-touch 边上的 corridor_id）
        ▼
阶段四读入：residual_graph_mapped.pkl  （见 §3.1 首步产物命名）
```

节点类型沿用 Step 3B：`wall`、`stub`；后续脚本可读入 `possible_corridor_wall`，但分类逻辑以原始 `stub` 为主。

边类型沿用 Step 3B 四种：

- `stub-stub-touch`：残差段端点链
- `corridor-stub-touch`：残差段接触边界墙（边上可带 `corridor_id`）
- `stub-stub-parallel`：残差段平行对
- `corridor-stub-parallel`：残差段与边界墙平行

分类逻辑：先niche,不是niche的所有短线都进行下一步，无论在什么簇里面。再判断“可能巷道墙体”，就是显然与已知巷道墙体共线的部分，其他未分类的，无论什么簇，都进行“辅巷道”判断。最后剩下的叫未分类
