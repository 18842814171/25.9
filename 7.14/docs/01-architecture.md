# 总体架构与实现进度

本文依据仓库现行代码与已落盘产物编写，并对照根目录《重要原则》说明设计约定与尚存差距。操作命令见各目录说明文档；本文只写阶段划分、数据流与进度。

## 一、问题与阶段划分

目标：从矿井通风系统图纸中识别标注与通风设施，并关联到巷道中心线结构图上。

| 阶段 | 目录 | 职责 | 实现状态 |
|------|------|------|----------|
| 图元导出 | `utils/` | 唯一直接读取图纸文件的入口；按模式写出根目录导出 JSON | 已稳定 |
| 第一阶段甲 | `step1a/` | 测点、钻孔等标注组合 | 已稳定；整图与局部图均有产物 |
| 第一阶段乙 | `step1b/` | 最终组与巷道名称关联到中心线结构图 | 已稳定；整图与局部图均有产物 |
| 第二阶段 | `stage2/` | 通风设施组合并关联 | 流水线已跑通 |

巷道中心线结构图（根目录 `{图号}-巷道_structure_graph.pkl`）由几何流水线另行产出，本仓库第一、二阶段将其作为关联底图输入，不在本仓库内重算中心线。

`stage1/readme.md` 为第一阶段（甲、乙）的计算逻辑总述；`stage1/` 下其余脚本为早期邻接实验代码，不参与现行主数据流。

## 二、统一数据入口

现行约定：各识别阶段不再直接读取图纸文件。

```text
图纸文件
  → utils/entity_export.py（配置：utils/entity_export_config.json）
  → 根目录导出 JSON
  → step1a / stage2 等脚本只读 JSON 与本阶段拓扑产物
```

| 导出模式 | 根目录产物（一名一义） |
|----------|------------------------|
| `text` | `{图号}-文字.json` |
| `line` | `{图号}-巷道.json` |
| `facility` | `{图号}-设施.json` |
| `legend` | `{图号}-图例.json` |

图例一次导出后，第一阶段甲的模板脚本按需要读取；设施导出独立进行。

## 三、主数据流

```text
【公共】
  entity_export（text / legend / facility / line）
       │
       ├─ 文字.json ──────────► 第一阶段甲 ──► 最终组图
       │                              │
       │                              ▼
       │                         第一阶段乙 ◄── 巷道中心线结构图
       │                              │
       │                              ▼
       │                         带标注结构图
       │                              │
       ├─ 图例.json ──► 甲：图例模板 / 识别规则
       │
       └─ 设施.json ──────────► 第二阶段 ──► 设施实例图
                                      │
                                      ▼
                               带设施结构图（底图为带标注结构图）
```

各多功能步骤拆成独立脚本顺序执行，不设总控入口。阶段间依赖仅为产物传递。

## 四、产物名称（全文统一）

| 逻辑名称 | 典型磁盘位置 |
|----------|----------------|
| 标注关系图 | `step1a/output/{图号}-retrieved_elements_graph` |
| 图例模板（标注） | `step1a/output/{图号}-retrieval_templates.json` |
| 识别规则 | `step1a/output/{图号}-retrieval_rules.json` |
| 候选组图 | `step1a/output/{图号}-candidate_cluster` |
| 最终组图 | `step1a/output/{图号}-final_cluster` |
| 带标注结构图 | `step1b/output/{图号}-structure_graph_with_texts` |
| 设施图元图 | `stage2/output/{图号}-facility_primitives_graph` |
| 设施实例图 | `stage2/output/{图号}-facility_graph` |
| 带设施结构图 | `stage2/output/{图号}-structure_graph_with_facilities` |

二进制图与同名可读摘要、核对图并存时，逻辑名称不变。勿另起同义别名或保留已废弃路径。

## 五、实现进度（相对已落盘产物）

以图号 `2026.1-1`（整图）与 `2026.1-1part`（局部图）为准。

### 第一阶段甲

- 整图：已产出标注关系图、图例模板、识别规则、候选组图、最终组图及核对图。
- 局部图：已引用整图识别规则完成候选组与最终组；最终组图约含测点 900、钻孔 58（整图计数）。
- 方法特点：以圆或块为锚，用文字角色与图层共现定类型，召回与可解释性较好。

### 第一阶段乙

- 整图与局部图均已产出带标注结构图（局部图另有核对图）。
- 关联距离由点到中心线距离的统计量推断；阈值集中在 `step1b/config.py`。

### 第二阶段

- 整图流水线（导出 → 图元图 → 实例图 → 关联 → 核对图）已跑通。
- 设施实例按端点连通分量组合，统一标为「通风设施」；图例模板匹配分型已移除。
- 后续拟改用深度学习目标检测或实例分割做设施类型识别。
